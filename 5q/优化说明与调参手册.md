# 智能小车循迹 —— 急弯冲出赛道的归因与优化

> 基线：队友可运行版本（`4.源码`，原样保留未改动）
> 本版：`5q/`，只改了 `Config/config.h` 和 `App/line.c` 两个文件
> 编译结果：**code 5893 字节 / data 106 字节 / 0 Error 0 Warning**
> 时钟：**11.0592 MHz**（注意，不是之前的 24MHz）

---

## 0. 先回答你的问题：改阈值，还是改权重？

**两个都不是主因，但"改权重"的方向是对的。**

| 你的方案 | 判断 | 原因 |
|---|---|---|
| 把 \|e\| 阈值从 12 降到 10 就改变轮速 | **基本无效** | 死区 `12` 在整条误差量程（约 ±200）里只占 6%，物理上对应约 **1.2mm** 的横向偏移。改成 10 等于 1.0mm，差 0.2mm。而且这块区域是"线正好在车中间"，恰恰不是出问题的位置 |
| 改四路加权系数（外层 2 → 3 或更大） | **方向对，但副作用大** | 它把误差量程从 200 扩大到 300，等于**整体增益放大到 1.5 倍，直道也一起变猛**，直道会开始画龙。而且满偏差时转向量只从 6 提到 9，仍然远远不够 |

真正的问题在下面这张表里。

### 这版代码的真实转向能力

误差定义：`error = (−2b₁ − b₂ + b₃ + 2b₄) − center_q`，其中 b₁…b₄ 是四路归一化强度（0~100，
左外/左内/右内/右外），`center_q` 是标定时"车骑在线上"的静态值。
数学范围 ±300，但物理上一条 20mm 黑线最多同时压住两个相邻探头，所以 **|error| 实际上限约 200**。

而转向量是 `trim = KP·error/100`，`KP = 3`：

| \|error\| | 转向量 trim | 左右 PWM（基准 20/18） | 差速比 |
|---|---|---|---|
| 40 | 1 | 20 / 16 | 1.25 |
| 80 | 2 | 19 / 13 | 1.46 |
| 120 | 4 | 20 / 10 | 2.00 |
| 160 | 5 | 19 / 7 | 2.71 |
| **200（理论最大）** | **6** | **18 / 6** | 3.00 |

**三条致命结论：**

1. **`MAX_TRIM = 18` 是个死参数**。要让它生效需要 `error = 600`，而误差最大只有 200。所以真实的转向上限就是 **6 个百分点**，代码里写的 18 从来没跑到过。
2. **满偏差时差速只有 18/6**。按差速模型 `R = d·(vL+vR) / (2(vR−vL))`（d 为轮距），最小转弯半径约 **1.4d**。轮距 100mm 的话就是 14cm —— 比赛道急弯还大，**物理上就拐不过去**，PID 再怎么调都没用。
3. 一旦线滑到外侧探头之外，`LineSeen()` 判定没线 → 进 `LINE_FINDING` → **1 秒找不到就 `Halt()` 永久停车**。这就是你看到的"跑出线外就停下"。

所以"没来得及转弯"不是反应慢，是**转向能力的绝对上限不够**。再加三条时间上的滞后：

| 滞后源 | 原来 | 影响 |
|---|---|---|
| 采样周期 | 10ms | 尚可 |
| 丢线确认帧 | 3 帧 = 30ms | 25% 占空比下相当于白跑约 7mm 才开始找线 |
| 电机斜坡 | 5%/20ms，改 12 个点要 3 步 = 60ms | 相当于先直行 1~2cm 才开始转 |
| 预判（D 项） | **完全没有**（`LINE_PID_KD = 0`） | 只能等误差出现才动，相位整整晚一拍 |

## 1. 改了哪 6 处

| # | 位置 | 参数 | 原值 | 现值 | 为什么 |
|---|---|---|---|---|---|
| 1 | `config.h` | `LINE_GAIN_LOW / HIGH` | 单一 `KP = 3` | **3 / 8** | 小偏差保持原手感（直道不抖），大偏差增益翻近 3 倍（过弯够猛） |
| 2 | `config.h` | `MAX_TRIM` | `18`（永不生效） | **`14`** | 变成真正生效的帽子。满舵 `26/0` = 内侧停转 = 原地转，这是这台车的转向能力上限 |
| 3 | `config.h` | `LINE_CURVE_SLOW` | 无 | **`4`**，下限 `12` | 弯道主动降速：\|e\| 每 100 降 4 个百分点。降速后同样的转向量能拐更小的弯 |
| 4 | `config.h` | `LINE_PID_KD` | `0`（关） | **`3`** | 微分 = 预判。偏差正在快速变大时提前多打一点，把相位滞后补回来 |
| 5 | `config.h` | `MOTOR_STEP_MS` | `20` | **`10`** | 斜坡响应快一倍，从直道打到满舵的时间从 60ms 降到 30ms |
| 6 | `line.c` | 失线救援 | 1s 超时、单向找线 | **1.6s + 后半程反向扫 + 枢轴 22%**，确认帧 3→2 | 冲出弯时车头是斜的，一次扫不到很正常。反向补扫能救回很多次，而不是直接永久停车 |

### 改动后的数值对照

| \|error\| | 旧 trim | 旧 L/R | **新 trim** | **新 L/R** | 说明 |
|---|---|---|---|---|---|
| 40 | 1 | 20/16 | **1** | **20/16** | 完全不变 ✔ 直道手感原样 |
| 60 | 2 | 20/14 | **2** | **20/14** | 完全不变 ✔ |
| 80 | 2 | 19/13 | **2** | **19/13** | 拐点，之后开始加强 |
| 100 | 3 | 19/11 | **4** | **20/10** | |
| 120 | 4 | 20/10 | **6** | **22/8** | |
| 140 | 4 | 19/9 | **8** | **23/5** | 这是正常过弯最常用的区间，转向量翻倍 |
| 160 | 5 | 19/7 | **10** | **24/2** | |
| 180 | 5 | 18/7 | **13** | **26/0** | 内侧停转，进入原地转向 |
| 200 | 6 | 18/6 | **14** | **26/0** | 满舵 |

**关键点：|error| ≤ 80 时输出与原版逐位相同。** 也就是说直道行为一个字节都没变，只有真进急弯才变凶——这正是"改权重"做不到的事（改权重会把直道一起放大）。

最小转弯半径：约 **1.4d → 0.5d**（内侧轮 0，绕停住的轮子转），也就是**能过的弯半径小了约 3 倍**。

## 2. 上车调参顺序（重要，一步一步来）

所有参数都在 `Config/config.h`，改完按 F7 重新编译烧录。**每一步只动一个参数。**

### 第 1 步：先确认直道没变坏

烧进去直接跑直道。因为 `|e| ≤ 80` 段完全没改，直道表现应该和队友那版一模一样。

> 如果直道开始左右抖 → 说明你车实际的误差量程比 200 小，跌进了加增益区。把 `LINE_GAIN_KNEE` 从 80 提到 110，或 `LINE_GAIN_HIGH` 从 8 降到 7。

### 第 2 步：跑那个拐不过去的急弯

| 现象 | 调法 |
|---|---|
| 还是冲出去 | `LINE_GAIN_HIGH` **+1**（8→9→10），一次只加 1 |
| 冲出去，且位置在弯的"出口" | `LINE_PID_KD` **+1**（提前量不够） |
| 冲出去，且车头明显已经斜着但还在加速 | `LINE_CURVE_SLOW` **+1**（4→5），降速不够 |

### 第 3 步：如果过了弯但开始"画龙"

| 现象 | 调法 |
|---|---|
| 弯里左右摆 | `LINE_PID_KD` **−1**，或 `LINE_GAIN_HIGH` **−1** |
| 出弯后摆两次才稳 | `LINE_PID_KD` **+1**（还不够阻尼） |
| 直道高速轻微抖 | `LINE_GAIN_LOW` **3 → 2** |

### 第 4 步：最后再提速度

`LINE_LEFT_BASE_PWM / LINE_RIGHT_BASE_PWM`（现 20/18）每档 **+2**，每档都重跑一遍急弯。
竞速想拿分，最终大概在 26~32/24~30 之间；再往上就必须要探头前移。

## 3. 如果调参到极限还是冲出去：三件物理的事

代码能给的转向能力已经给满了（满舵 26/0 = 原地转）。剩下的必须动机械：

1. **探头往前伸 20~30mm**（最重要）。探头在车轴线上时，等它发现偏差，车身已经偏了；前伸 25mm 相当于白送 25mm 的提前量，效果比调任何参数都大。前伸的代价是要改标定时的中心位置，代码里 `SetCenterReference()` 会自动重算 `center_q`，不用改代码。
2. **降基准速度**：`20/18 → 18/16`，直接换转弯余量，代价是慢。
3. **重心前移 / 减小轮距**：轮距 d 越小，同样差速下的转弯半径越小（`R ∝ d`）。

## 4. 编译与下载（这一版和之前不一样，务必看）

### 4.1 时钟是 11.0592 MHz

队友这版的 `config.h` 第一行就写死了：

```c
#define SYSCLK_HZ  11059200UL
```

**STC-ISP 里 IRC 频率必须选 11.0592MHz**，不能选 24MHz。选错了所有定时（200ms 采样、2000ms 启动延时、电机斜坡）都会变成 2.17 倍快，表现为"上电就冲、OLED 乱跳"。

### 4.2 打开与编译

直接双击 `5q\car.uvproj`，按 F7。器件、11.0592MHz、头文件路径都已经配好（沿用队友的工程）。
命令行自检：

```bash
D:/AppGallery/Keil/UV4/UV4.exe -b car.uvproj -j0 -o build.log
```

当前结果是 0 Error / **2 Warning**，那两条 `UNCALLED SEGMENT ?PR?MOTOR_GETA/?PR?MOTOR_GETB` 是队友原工程就有的（`Motor_GetA/GetB` 只在超声避障模式里用），**无害，可以不理**。

### 4.3 标定流程（沿用队友的设计，按键是 P3.3）

1. 上电 → 屏幕 `HOLD P3.3 TO TEST` / `WAIT FOR CAL`，**3 秒内不按**就进标定。
2. 依次：`ALL 4 ON WHITE`（四路都压白，按住 P3.3 保存）→ 四路分别压黑线中心（`1 LEFT OUT` … `4 RIGHT OUT`）→ `CENTER CAR ON LINE`（车骑在线上，线在两内探头之间）。
3. 屏幕显示四路 `W/B` 值和 `MID` 值，**确认 `B − W` 大于 120**（`MIN_CAL_SPAN`），否则会提示 `LOW ADC SPAN`。
4. 显示 `CAL DONE` 后按住 P3.3 → 延时 2 秒开始跑。

> 标定值存在 RAM 里，**断电就丢**。每次换场地、换电池、拆装探头都要重标。

## 6. 代码阅读提示：三个函数就够了

```
Line_Task()       每 10ms 一次：读 4 路 ADC → 算 error → 算 trim → 输出 PWM
  └ SteeringTrim(error)   误差 → 转向量（这里是我改的变增益 + 微分）
  └ DriveTrim(trim, mag)  转向量 + 弯道降速 → 左右 PWM
  └ FindLine(now)         丢线后的找线动作（我改了反向补扫）

ReadLineError()   4 路强度加权 → q - center_q = error；同时判断有没有线
Strength()        单路 ADC 归一化成 0~100（用这一路自己的白/黑阈值）
```

误差符号约定（**和你们之前那版相反，别搞混**）：

```
error > 0  →  黑线在车体右侧  →  左轮快、右轮慢  →  向右转
error < 0  →  黑线在车体左侧  →  左轮慢、右轮快  →  向左转
```

`center_q` 是标定时"车正好骑在线上"算出来的 q，减掉它就把"探头安装不对称"和"车体没对正"的固定偏差消掉了。所以**换探头位置后不用改代码，重标一次就行**。

---

## 7. 一句话总结

> 我没按"改阈值"或"改权重"来做，因为前者量级差了 100 倍，后者会把直道一起搞猛。
> 我用的是**变增益**：直道段（|e|≤80）与原版逐位相同，急弯段把转向量从 6 提到 14，
> 再配上**弯道降速 + 微分预判 + 失线反向补扫**，把"拐不过来"和"拐不过来就停车"两件事一起解决。
